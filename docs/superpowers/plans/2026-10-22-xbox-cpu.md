# Xbox CPU work reduction implementation plan

> **For agentic workers:** Use test-driven development for the independent tasks below.

**Goal:** Implement the seven CPU candidates the user approved from the source assessment.

**Architecture:** Reuse current queues, snapshot ownership and UI elements. Reduce
repeated work without changing game simulation, mod callbacks or stored data.
FIFO batching is a conservative four-draw experiment, still requiring hardware A/B.

**Tech stack:** C++20, Aurora, Abseil, RmlUi, GoogleTest/CTest; Windows UWP CI.

**Spec:** `docs/xbox-one-s-1080p60-assessment.md`, CPU candidate sections.

## Constraints and review focus

- Preserve every explicit FIFO publication/drain and DrawDone ordering.
- Recycled interpolation buffers must discard stale entries on object deletion,
  epoch changes and interpolation changes; callbacks retain valid ownership.
- Shader priority state must follow promotion, worker dequeue and shutdown.
- Texture deduplication retains priority refreshes and owned snapshots; registry
  lock precedes job lock. Publication keeps stable ties and oversized progress.
- HUD guards must allow settings changes, progress completion and corner avoidance.
- Preserve native-mod hooks, game timing, saves, ISO and persistent caches.
- Cache budgets, worker counts and limiter sleep/spin remain profiling experiments,
  rather than automatic changes to unrelated behavior.

## Tasks

1. **Render queues:** in Aurora FIFO/pipeline cache and their tests, first assert
   four-draw publication, explicit flush correctness and no repeat promotion scan.
   Implement batch four and pending background-state tracking. Run FIFO/queue tests.
2. **Interpolation:** in frame/material interpolation and standalone tests, assert
   allocation reuse, stale-entry removal and callback ownership. Reuse matrix
   buffers and material storage only when no callback owns it. Run regression tests.
3. **Texture streaming:** in Aurora streaming implementation/tests, first assert
   repeated pending requests do not allocate snapshots. Delay snapshot construction,
   combine queue locking and snapshot priorities before sorting outside the lock;
   retain scratch capacity. Run streaming/stale-source tests.
4. **HUD:** in overlay and private helpers/tests, assert unchanged attributes/styles
   produce no new updates and changed values still apply. Guard repeated FPS and
   shader-progress updates. Run headless tests against pinned RmlUi.
5. **Integration:** review all diffs, run relevant suites, push Aurora submodule
   before updating the parent pointer. Build a signed UWP package on the existing
   Windows workflow and report exact results. Hardware timing and visual/gameplay
   validation remain explicit limits until measured.
